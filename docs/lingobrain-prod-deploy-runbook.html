Deploy LingoBrain lên VPS

Hướng dẫn cho người vận hành: triển khai lần đầu, cập nhật phiên bản và phục hồi khi có sự cố. Các khối SERVER chạy trong Bash trên VPS; các khối WINDOWS chạy trong PowerShell trên máy của bạn.

Phạm vi kiểm chứng: đã đọc tài liệu nguồn và đối chiếu Compose, script deploy, script backup tại máy local. Chưa SSH, build Docker, kiểm tra DNS hay thực hiện deploy trên VPS. Các kết quả bên dưới là tiêu chí cần kiểm tra, không phải báo cáo đã chạy thành công.

Repo Goals chỉ chứa tài liệu. Clone repo ứng dụng ở trên để deploy. Nếu chọn domain khác, thay toàn bộ domain trong cấu hình Caddy và các lệnh kiểm tra.

  • VPS đã có Docker Engine và Compose plugin, Git, OpenSSL; SSH bằng key đã hoạt động.
  • Caddy dùng chung đang quản lý cổng 80/443, có mạng Docker web, và Caddyfile đã import các file trong /etc/caddy/sites/, tương ứng thư mục host /srv/caddy/conf/sites/.
  • User deploy có quyền dùng Docker, ghi vào /srv/apps và thư mục cấu hình site Caddy. DNS của domain phải trỏ đúng VPS; kiểm tra cả AAAA nếu có.
  • Chốt trước có giữ tài khoản cũ hay không. Nếu có, xem mục 7 trước khi cho người dùng đăng ký trên VPS mới.

2. Deploy lần đầu

2.1. Clone và tạo cấu hình

SERVER

cd /srv/apps && git clone --depth 1 https://github.com/congvu99/LingoBrain.git lingobrain
cd /srv/apps/lingobrain
git log --oneline -1
ls Dockerfile compose.yml deploy/deploy.sh deploy/backup.sh
(
  set -eu
  umask 077
  if [ ! -e .env ]; then
    password=$(openssl rand -hex 24)
    printf 'DB_PASSWORD=%s\n' "$password" > .env
  fi
  chmod 600 .env
  grep -q '^DB_PASSWORD=.' .env
)
ls -l .env
sudo install -d -o deploy -g deploy -m 700 /srv/backups/lingobrain

Nếu clone lỗi, dừng để xử lý trước khi chạy tiếp. Nếu thư mục đã có repo, kiểm tra git remote -v và git status, không xóa thư mục để clone lại. Khối tạo .env giữ nguyên file đã tồn tại; nếu thiếu DB_PASSWORD, sửa bằng trình soạn thảo và giữ đúng mật khẩu DB hiện hữu.

PostgreSQL nhận mật khẩu khởi tạo khi volume còn trống. Đổi DB_PASSWORD trong .env không tự đổi mật khẩu DB đã tồn tại. Không commit .env hoặc dùng down -v để chữa lỗi kết nối.

2.2. Build và khởi chạy

SERVER

cd /srv/apps/lingobrain
bash deploy/deploy.sh
docker compose ps
docker compose logs --tail 60 app db

Script pull fast-forward, build image theo commit, khởi động dịch vụ rồi kiểm tra /api/words tối đa 45 lượt, cách nhau 2 giây ngoài thời gian request. Thành công in deploy ok: <commit>. App tự nạp bộ từ và audio index từ nội dung repository.

Nếu script trả lỗi, kiểm tra log trước. Lần đầu chưa có image đã deploy để rollback. Trạng thái container healthy chưa thay thế được kiểm tra API và thao tác người dùng.

2.3. Gắn domain vào Caddy dùng chung

Kiểm tra DNS đã trỏ đúng VPS. Nếu file site đã tồn tại, lưu bản sao ngoài thư mục được import rồi chỉnh file hiện có; khối dưới chỉ dành cho site mới.

SERVER — tạo file mới, không ghi đè file cũ

(
  set -eu
  set -o noclobber
  cat > /srv/caddy/conf/sites/lingobrain.caddy <<'EOF'
lingobrain.congvu.duckdns.org {
    encode zstd gzip
    reverse_proxy lingobrain:3000
}
EOF
)
cd /srv/caddy
docker compose exec caddy caddy validate --config /etc/caddy/Caddyfile && \
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile

Chỉ reload khi validate thành công. Nếu báo lỗi, sửa cấu hình và validate lại.

3. Nghiệm thu sau mỗi lần deploy

WINDOWS

Resolve-DnsName lingobrain.congvu.duckdns.org
curl.exe -sS -o NUL -w "%{http_code}\n" https://lingobrain.congvu.duckdns.org/
curl.exe -sS -o NUL -w "%{http_code}\n" https://lingobrain.congvu.duckdns.org/api/words
curl.exe -sS -o NUL -w "%{http_code}\n" https://lingobrain.congvu.duckdns.org/.env

Ba HTTP status mong đợi lần lượt là 200, 200, 404. Không dùng -k để bỏ qua lỗi chứng chỉ. Trang chủ 200 chưa chứng minh DB hoạt động; phải kiểm tra /api/words.

SERVER

cd /srv/apps/lingobrain
docker compose ps
docker compose port app 3000
docker compose port db 5432
sudo ss -tlnp

App và DB không được publish cổng ra host: hai lệnh compose port không được trả địa chỉ cổng host (có thể báo chưa publish). Đối chiếu các cổng đang nghe với dịch vụ thực tế trên VPS dùng chung.

  • Mở HTTPS, đăng ký/đăng nhập tài khoản thử.
  • Ôn một thẻ trên máy A, đăng nhập cùng tài khoản trên máy B và kiểm tra đồng bộ.
  • Kiểm tra audio; nếu dùng PWA, thêm vào màn hình chính rồi kiểm tra mở offline sau khi nội dung đã được tải.
  • Ghi lại commit, thời điểm deploy, kết quả API và bản backup gần nhất.

4. Cập nhật và rollback ứng dụng

Sửa code ở repo ứng dụng rồi push. Theo tài liệu nguồn, khi đổi JS/CSS/HTML cần tăng APP_VERSION trong js/app-storage.js và CACHE trong sw.js cho khớp để PWA nhận bản mới.

WINDOWS

ssh vps "cd /srv/apps/lingobrain && bash deploy/deploy.sh"
  • deploy ok: tiếp tục nghiệm thu mục 3.
  • already at: commit đã ghi trong .deployed-tag; vẫn cần kiểm tra dịch vụ. Dùng FORCE=1 bash deploy/deploy.sh khi chủ động cần build lại.
  • deploy FAILED … rolled back: script đã yêu cầu chạy image trước; tự kiểm tra lại API vì script không kiểm tra sức khỏe sau rollback.
  • deploy khác đang chạy: chờ lần trước kết thúc, không xóa lock để chạy chồng.

Script backup trước khi thay container nếu đã có .deployed-tag. Rollback image không phục hồi dữ liệu hoặc schema DB. Chỉ rollback khi bản cũ tương thích dữ liệu hiện tại.

SERVER — rollback thủ công sau khi chọn tag tương thích

cd /srv/apps/lingobrain
docker images lingobrain
# Thay COMMIT_CU bằng tag thực sự có trong danh sách:
IMAGE_TAG=COMMIT_CU docker compose up -d --no-build app

Chạy lại mục 3. Rollback thủ công không cập nhật .deployed-tag hay tag latest; ghi nhận trạng thái này trước lần deploy sau và dùng FORCE=1 nếu script bỏ qua commit cần triển khai lại.

5. Backup và bản sao ngoài VPS

Script dùng pg_dump -Fc, bỏ dữ liệu bảng tts_clips, giữ file dump trong 14 ngày. Đây là dump DB, không chỉ riêng tài khoản và tiến độ.

SERVER

cd /srv/apps/lingobrain
bash deploy/backup.sh
ls -lh /srv/backups/lingobrain/
date
crontab -e

Chỉ thêm một dòng lịch bên dưới vào crontab của user deploy. Giờ 03:45 là giờ của hệ thống cron trên VPS; đối chiếu date trước khi chọn lịch.

NỘI DUNG CRONTAB

45 3 * * * cd /srv/apps/lingobrain && bash deploy/backup.sh >> /srv/backups/lingobrain/backup.log 2>&1

Kiểm tra ngày hôm sau: tail /srv/backups/lingobrain/backup.log phải có backup ok và file dump mới có dung lượng hợp lý.

WINDOWS — sao chép định kỳ ra ngoài VPS

New-Item -ItemType Directory -Force D:\backup\lingobrain
scp "vps:/srv/backups/lingobrain/lingobrain-*.dump" D:\backup\lingobrain\

Bảo vệ thư mục backup vì dump chứa dữ liệu tài khoản và hash mật khẩu. Giữ thêm bản sao .env ở nơi lưu bí mật phù hợp, ngoài Git. Lịch sao chép ra ngoài VPS quyết định lượng dữ liệu có thể mất khi VPS hỏng hoàn toàn; cần thử phục hồi trên môi trường riêng định kỳ.

6. Khôi phục DB từ backup

Thao tác này ghi đè dữ liệu tương ứng trong DB đích và cần thời gian dừng ứng dụng. Chọn đúng file dump, tạo backup hiện trạng và thử phục hồi riêng trước khi áp dụng lên production. Không xóa volume.

SERVER — chuẩn bị

cd /srv/apps/lingobrain
ls -lh /srv/backups/lingobrain/
docker compose stop app
bash deploy/backup.sh

Chỉ tiếp tục khi backup hiện trạng thành công. Thay đường dẫn mẫu bằng file dump muốn phục hồi, không chọn nhầm bản vừa tạo.

SERVER — phục hồi; chỉ bật app khi restore thành công

docker compose exec -T db pg_restore -U lingo -d lingobrain \
  --no-owner --no-acl --clean --if-exists --exit-on-error --single-transaction \
  < /srv/backups/lingobrain/lingobrain-YYYYMMDD-HHMMSS.dump && \
docker compose start app

Nếu restore lỗi, giữ app dừng và đọc lỗi để xử lý; không coi dữ liệu đã phục hồi. Khi thành công, chạy nghiệm thu mục 3 và kiểm tra tài khoản/tiến độ đại diện. Không dựa vào dữ liệu trên thiết bị người dùng để thay thế backup server.

7. Chuyển người dùng từ Nhân Hòa

Giữ tài khoản cũ: lấy dump từ hệ thống nguồn, ghi nhận phiên bản PostgreSQL và số lượng tài khoản. Thử restore vào DB riêng với phiên bản tương thích trước; chốt cửa sổ ngừng ghi ở nguồn, lấy dump cuối cùng, sao lưu đích rồi thực hiện mục 6. Đối chiếu số tài khoản và kiểm thử đăng nhập trước khi mở lại cho người dùng.

Quy trình mục 6 dành cho dump custom của PostgreSQL. File SQL/SQL.GZ cần quy trình import riêng đã thử nghiệm; không đổi đuôi file thành .dump, không tự lọc lệnh SQL bằng grep hoặc xóa volume để import.

Không chuyển DB cũ: VPS bắt đầu với tài khoản trống. Theo tài liệu nguồn, khi giữ cùng origin, tiến độ local có thể gộp lên sau khi đăng ký lại đúng tên; cần thử trên tài khoản mẫu trước khi hướng dẫn đại trà.

Đổi domain: người dùng tải backup ở web cũ, đăng ký/đăng nhập ở web mới rồi khôi phục; cài lại PWA. Theo tài liệu nguồn, bản ghi âm shadowing không nằm trong backup. Giữ web cũ khả dụng trong thời gian chuyển đổi đã thông báo; chỉ đóng hệ thống cũ khi đã kiểm tra dữ liệu và bản sao lưu.

8. Bật hội thoại AI — tùy chọn

Thêm key vào .env bằng trình soạn thảo trên server. Không đưa key vào Git. Hạn mức và model phụ thuộc tài khoản nhà cung cấp; kiểm tra thông tin thực tế trước khi cấu hình.

FILE .env — thêm vào, giữ DB_PASSWORD hiện có

GEMINI_API_KEY=THAY_BANG_KEY_CUA_BAN
DIALOGUE_DAILY_MAX=10
# Tùy chọn: GEMINI_MODEL_FALLBACK, DIALOGUE_LEARNER_CONTEXT

SERVER

cd /srv/apps/lingobrain
docker compose up -d --force-recreate app
docker compose exec -T app wget -qO- http://127.0.0.1:3000/api/dialogue
docker compose logs --tail 50 app

{"enabled":true} chỉ xác nhận tính năng được bật, chưa chứng minh key hợp lệ. Đăng nhập, ôn ít nhất một thẻ rồi thử tạo hội thoại. Kiểm tra log khi gặp lỗi QUOTA, UPSTREAM, INVALID hoặc BUSY.

9. Xử lý sự cố

Hiện tượngKiểm tra và xử lý
Clone báo thư mục tồn tạiKiểm tra remote và trạng thái Git trong thư mục; dùng repo hiện hữu nếu đúng. Không xóa khi chưa biết dữ liệu bên trong.
Permission deniedKiểm tra whoami, owner của đúng thư mục và quyền Docker. Nếu vừa thêm nhóm docker, đăng nhập SSH lại. Không chown cả /srv/backups của mọi ứng dụng.
Thiếu mạng webKiểm tra mạng của Caddy dùng chung và cấu hình Compose trước khi tạo/kết nối mạng.
Git không fast-forwardChạy git status, git diff, lưu thay đổi server rồi xử lý xung đột. Không reset --hard để bỏ qua thay đổi chưa rõ nguồn gốc.
502Kiểm tra app bằng docker compose ps và log; Caddy phải chung mạng web, proxy tới lingobrain:3000.
Đăng nhập hoặc /api/words trả 503Xem log app/db, trạng thái DB, lỗi seed và mật khẩu. Nếu .env bị thay đổi, khôi phục mật khẩu đúng hoặc thực hiện đổi mật khẩu DB có kiểm soát.
429 khi đăng nhậpĐối chiếu chuỗi proxy với TRUST_PROXY_HOPS (Compose hiện đặt 1). Không tăng số hop khi chưa kiểm tra đường truy cập trực tiếp và proxy tin cậy.
PWA còn bản cũKiểm tra APP_VERSION/CACHE, commit đã push và commit server đã deploy, đóng/mở lại app. Backup tiến độ trước khi xóa dữ liệu trình duyệt.
